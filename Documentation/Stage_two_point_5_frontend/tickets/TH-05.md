# EHB Ticket TH-05 — Click an Account to See Its Details

## Objective

Make each account in the list a clickable link that opens a details page for
that one account, at a URL like `/accounts/1111`.

---

## Background for beginners

### Dynamic URLs and `@PathVariable`

A details page needs to know *which* account. We put the account number into the
URL itself:

```text
/accounts/1111
/accounts/2222
```

The part that changes (`1111`, `2222`) is a **path variable**. In the controller
you capture it with `@PathVariable` — exactly as your REST `AccountController`
already does:

```java
@GetMapping("/accounts/{accountNumber}")
public String accountDetails(@PathVariable String accountNumber, Model model) {
    ...
}
```

The `{accountNumber}` in the path and the parameter name match up, so Spring
hands you whatever was in that slot of the URL.

> **Same tool, different output.** Your REST controller also uses
> `@PathVariable`. The *only* difference here is the return value: the REST
> method returns an `AccountResponse` (becomes JSON); this MVC method returns a
> **view name** (becomes HTML).

### `th:href` — building links safely

To link to the right URL for each account you build the href from data. Use
Thymeleaf's URL syntax `@{...}`:

```html
<a th:href="@{/accounts/{num}(num=${account.accountNumber})}">View</a>
```

- `@{...}` builds a URL that correctly includes your app's context path.
- `{num}` is a placeholder filled by the `(num=...)` part.
- So for account `1111` this renders as `href="/accounts/1111"`.

### Looking up one account

`AccountService` already has:

```java
Account getAccountByNumber(String accountNumber)   // throws AccountNotFoundException if missing
```

Use it, then map to `AccountResponse` as before.

## Worked example (a *product* details page, so you build the account one)

**List page link (inside the `th:each` row):**

```html
<td>
    <a th:href="@{/products/{id}(id=${product.id})}">View</a>
</td>
```

**Details controller:**

```java
@GetMapping("/products/{id}")
public String productDetails(@PathVariable String id, Model model) {
    ProductResponse product = ProductResponse.from(productService.getById(id));
    model.addAttribute("product", product);
    return "product-details"; // -> templates/product-details.html
}
```

**`product-details.html`:**

```html
<body>
    <h1 th:text="${product.name}">name</h1>
    <p>Price: <span th:text="${product.price}">price</span></p>
</body>
```

## Your task

1. On your accounts list (TH-04), add a link in each row that points to
   `/accounts/{accountNumber}` using `th:href` and `@{...}`.
2. Add a new method in `UIController` for `GET /accounts/{accountNumber}` with a
   `@PathVariable`. Look up the account via `accountService.getAccountByNumber`,
   map it to `AccountResponse`, add it to the model, and return a new view name
   (e.g. `account-details`).
3. Create `src/main/resources/templates/account-details.html` showing at least:
   - account number;
   - currency;
   - balance.

## Verify

- From the list, click several different accounts. The browser URL should change
  to `/accounts/1111`, `/accounts/2222`, etc., and the page should show the
  matching account.
- Note that the account numbers (`1111`–`5555`) are stable across restarts, so
  these links keep working. (Businesses in TH-07 will be different — their IDs
  are random UUIDs.)

## Concepts practised

- `@PathVariable` in an MVC controller;
- `th:href` and the `@{...}` URL syntax;
- multiple templates in one application;
- contrasting a view-returning method with a DTO-returning REST method.

## Done when

- each listed account links to its own details page;
- the URL and the displayed account always match.
