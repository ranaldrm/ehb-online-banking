# EHB Ticket TH-12 — Add Simple Navigation (and Tidy Up)

## Objective

Make it possible to move around the UI with links, instead of typing URLs by
hand. Optionally remove obvious duplication between templates — but only if it
genuinely helps.

---

## Background for beginners

### Static links

For a fixed destination you don't even need Thymeleaf — a plain link works:

```html
<a href="/">Home</a>
```

Use `th:href="@{...}"` only when the URL is built from data (as in the account
and business links). For top-level navigation like Home / Accounts / Businesses
/ New payment, static `<a href="...">` links are perfectly fine.

### Optional: Thymeleaf fragments (only if duplication is bothering you)

If the same block of HTML (say a little nav bar) is copy-pasted into several
templates, Thymeleaf lets you define it once and include it. Define a fragment:

```html
<!-- templates/fragments/nav.html -->
<nav th:fragment="mainNav">
    <a href="/">Home</a> |
    <a href="/accounts">Accounts</a> |
    <a href="/businesses">Businesses</a>
</nav>
```

Include it in a page:

```html
<div th:replace="~{fragments/nav :: mainNav}"></div>
```

`th:replace` swaps that `<div>` for the fragment's content. This is the *only*
Thymeleaf layout feature you might use here, and only if it clearly reduces
duplication.

> **Scope warning — do not over-build.** You do **not** need a layout library,
> CSS, a styled navigation bar, responsive design, or a fragment for every
> repeated element. A handful of plain links is enough to call this ticket done.
> Resisting unnecessary abstraction is part of the exercise.

---

## Worked example

A minimal set of links placed near the top of each main page:

```html
<nav>
    <a href="/">Home</a> |
    <a href="/accounts">Accounts</a> |
    <a href="/businesses">Businesses</a> |
    <a href="/payments/new">New payment</a>
</nav>
```

On a details page, a "back" link helps too:

```html
<a href="/accounts">Back to all accounts</a>
```

(Adjust the paths to whatever routes you actually chose in the earlier tickets.)

> **Note: you may need to move the accounts list.** The examples above assume a
> separate `/accounts` page, but in TH-04 the accounts table was built into the
> home page (`GET /`), and `/accounts/{accountNumber}` is only the per-account
> details page. By now the home page may also have a businesses link, so it
> would be better as a simple landing page. Decide which of these you prefer:
>
> - **Leave the accounts table on `/`** and point the "Accounts" link at `/`.
> - **Move the accounts table to its own `GET /accounts` page** (new handler and
>   template, in the same style as `/businesses`) and make `/` a plain landing
>   page. This matches the examples and keeps the URL scheme consistent, but
>   it means moving the code and updating any links that pointed at `/`.
>
> Either is fine. Pick one, and make sure the "Back to all accounts" link on the
> details page goes to wherever the accounts list actually lives.

## Your task

1. Add plain navigation links so that, once you're in the UI, you can reach:
   - the home / accounts list;
   - the businesses list;
   - the payment form;
   - and get back from a details page to its list.
2. Skim your templates for anything genuinely confusing or heavily duplicated. If
   a nav block is repeated across several pages and that bothers you, you may
   extract a single fragment with `th:fragment` / `th:replace`. Otherwise leave
   it alone.

## Verify

Starting from the home page, perform the main journeys — view accounts, open an
account, view businesses, open a business, go to the payment form — using only
clicks, never typing a URL into the address bar.

## Concepts practised

- static vs data-driven links;
- (optionally) Thymeleaf fragments for reuse;
- keeping a small multi-page app navigable without over-engineering it.

## Done when

- every main page is reachable by clicking;
- no CSS or layout framework was introduced;
- any fragment you added clearly reduced duplication rather than adding ceremony.
