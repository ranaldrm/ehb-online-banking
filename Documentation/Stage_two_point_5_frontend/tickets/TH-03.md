# EHB Ticket TH-03 — Pass Data From Java Into the Page

## Objective

Send one simple value from your Java controller into the HTML page and display
it with Thymeleaf. Still no banking data — just one string — so you can focus on
the mechanism.

---

## Background for beginners

### The `Model` is a box of data for the page

Spring MVC gives your controller method a `Model` object. Think of it as a
labelled box. You put values in with a name (a "key"); the template reads them
back out by that name.

```java
model.addAttribute("pageStatus", "All systems go");
//                   ^key           ^value
```

In the template you then refer to the value with `${pageStatus}`.

### `th:text` writes a value into an element

```html
<p th:text="${pageStatus}">placeholder text</p>
```

- `${pageStatus}` looks up the `pageStatus` attribute from the model.
- `th:text` **replaces the element's text content** with that value when
  rendered.
- The `placeholder text` between the tags is only shown if you open the raw
  `.html` file directly in a browser (handy for designers). When Spring renders
  the page, Thymeleaf overwrites it with the model value. So you are *not*
  hard-coding the real value in the HTML.

### The lifecycle

```text
Controller puts data in the Model
        ↓
Spring hands the Model to Thymeleaf
        ↓
Thymeleaf fills the template
        ↓
browser receives finished HTML
```

This is the key difference from the old JavaScript plan: there, the browser
loaded an empty page and *then* made a second `fetch()` call for data. Here the
page arrives **already complete**. One request, one finished page.

## Worked example (different value, so you write the EHB one)

**Controller method:**

```java
@GetMapping("/hello")
public String hello(Model model) {           // Spring passes you a Model
    model.addAttribute("greeting", "Hello there");
    return "greeting";
}
```

**Template `greeting.html`:**

```html
<body>
    <h1 th:text="${greeting}">placeholder heading</h1>
</body>
```

Rendered result in the browser:

```html
<body>
    <h1>Hello there</h1>
</body>
```

## Your task

1. Open `UIController`. The `bankHome` method already has a `Model` parameter.
   - **Check the import.** It must be `org.springframework.ui.Model`. If it is
     anything else (an IDE sometimes imports a different `Model`), fix it now,
     or the project will not compile once you call `model.addAttribute(...)`.
2. In `bankHome`, add a simple attribute to the model — for example a status
   message such as `"EHB UI is running"`. Choose your own key name.
3. In `bankhome.html`, display that value with `th:text`. Do **not** type the
   literal message into the HTML — read it from the model.

## Verify

1. Start the app and open `http://localhost:8080/`. You should see your message.
2. Now the important test: change the message **in the Java code**, restart, and
   reload the page. The page must show the new value. That proves the text came
   from Java, not from the HTML.

## Reflection

- With the old JavaScript approach the browser fetched the data separately after
  loading the page. Here the server produced the finished HTML. What are the
  trade-offs? (Think about: number of requests, where the logic lives, what the
  browser needs to be capable of.)

## Concepts practised

- Spring MVC `Model` and model attributes;
- `${...}` expressions;
- `th:text`;
- server-side rendering vs client-side fetching.

## Done when

- the page shows a value that originates in Java;
- changing the Java value changes what the page shows;
- the value is not hard-coded in the HTML.
