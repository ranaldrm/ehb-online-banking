# EHB Ticket TH-13 — Confirm the REST API Still Works

## Objective

Prove that adding the Thymeleaf UI did not break the REST API from Stage 2. The
application should now serve **two** front doors over the same services.

---

## Background for beginners

### Two presentation layers, one brain

```text
REST client → @RestController ┐
                              ├→ Services → Repository → Domain
Browser     → @Controller ────┘
```

Both controller types are just *adapters*. They translate an incoming request
into a service call and translate the result back out — one into JSON, one into
HTML. Neither contains banking rules; those live in the services and domain.
That is why both can safely call the same service, and why neither should ever
call the other.

---

## Your task

### 1. Run the test suite

```bash
mvn test
```

All existing Stage 1 and Stage 2 tests must still pass. You added UI code and
templates; you should not have changed service or domain behaviour, so nothing
should have broken. If something is red, that is a real regression to fix.

### 2. Spot-check the REST endpoints by hand

With the app running (`mvn spring-boot:run`), check a representative sample in
Postman or a browser. These should all still return **JSON** (or plain text for
status), exactly as before the UI existed:

```text
GET  http://localhost:8080/api/status
GET  http://localhost:8080/api/accounts
GET  http://localhost:8080/api/accounts/1111
GET  http://localhost:8080/api/accounts/1111/transactions
POST http://localhost:8080/api/accounts/1111/deposit      body: { "depositAmount": 25.00 }
POST http://localhost:8080/api/accounts/1111/withdraw     body: { "withdrawAmount": 10.00 }
POST http://localhost:8080/api/payments                   body: { "sourceAccountNumber": "1111", "targetAccountNumber": "4444", "paymentAmount": 5.00 }
GET  http://localhost:8080/api/businesses
```

(Remember business detail lookups need a current UUID, which you can grab from
`GET /api/businesses`.)

### 3. Confirm the UI returns HTML

Open `http://localhost:8080/` and your other UI routes in a browser. These
return **HTML**, not JSON.

### 4. Check the dependency direction

Confirm you did **not** make any `@RestController` depend on a UI controller or
on Thymeleaf, and that the UI controller calls the services directly rather than
making HTTP calls to `/api/...`.

## Reflection — be able to answer

- Why can both controller types call the same service without conflict?
- Why shouldn't the Thymeleaf controller call the REST controller?
- Why would it be wrong for the server to make HTTP requests to its own
  `/api/...` endpoints just to reuse them? (Think: extra network hop, serializing
  then deserializing your own data, losing exceptions/types.)
- Which layer actually contains the banking rules?

## Done when

- `mvn test` is green;
- the sampled REST endpoints still return their expected JSON/plain-text;
- the UI routes return HTML;
- REST and UI controllers both depend only on the service layer.
