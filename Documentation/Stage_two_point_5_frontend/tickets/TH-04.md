# EHB Ticket TH-04 — Display All Accounts in a Table

## Objective

Show every seeded account on the home page, in a plain HTML table, using the
real account data from `AccountService`.

---

## Background for beginners

### Getting the data: go through the service, not the repository

Your controller should ask the **service** layer for data, exactly like your
REST controllers do. The service is the application's "front desk"; the
repository is storage behind it. Keep that boundary:

```text
UIController → AccountService → AccountRepository
```

Do **not** inject `AccountRepository` into the UI controller. Do not create a
second copy of the data. There is one source of truth.

The method you need already exists:

```java
List<Account> getAllAccounts()   // on AccountService
```

### Turning domain objects into display objects

Your REST layer never hands raw `Account` domain objects to the outside world —
it converts them to an `AccountResponse` record first. Do the same here so the
template only sees display-safe fields. `AccountResponse` has a ready-made
factory:

```java
AccountResponse.from(account)
```

`AccountResponse` exposes exactly these fields (remember these names — the
template uses them):

- `accountNumber`
- `currency`
- `balance`

### `th:each` — the Thymeleaf "for each" loop

`th:each` repeats one HTML element once per item in a collection:

```html
<tr th:each="item : ${items}">
    <td th:text="${item.name}">name</td>
</tr>
```

Read it as: "for each `item` in `items`, produce one `<tr>`". Inside that row
you refer to the current element as `item`.

For a record like `AccountResponse`, `${account.accountNumber}` calls the
generated `accountNumber()` accessor automatically — you just write the field
name.

---

## Worked example (a *products* table, so you build the accounts one yourself)

**Controller:**

```java
@GetMapping("/products")
public String products(Model model) {
    List<ProductResponse> products = productService.getAll()
            .stream()
            .map(ProductResponse::from)
            .toList();
    model.addAttribute("products", products);
    return "products";
}
```

**Template `products.html` (inside `<body>`):**

```html
<table>
    <tr>
        <th>Name</th>
        <th>Price</th>
    </tr>
    <tr th:each="product : ${products}">
        <td th:text="${product.name}">name</td>
        <td th:text="${product.price}">price</td>
    </tr>
</table>
```

The first `<tr>` (the header row) has no `th:each`, so it appears once. The
second `<tr>` repeats for every product.

## Your task

1. Read `AccountService.getAllAccounts()`, the `AccountResponse` record, and
   `AccountController.getAllAccounts()` to see how the REST side already maps
   accounts to `AccountResponse`.
2. In `UIController` (either in `bankHome` or a new `/accounts` page method —
   your choice), call `accountService.getAllAccounts()`, map each `Account` to
   an `AccountResponse`, and add the resulting list to the model.
3. In the template, use `th:each` to render one table row per account showing:
   - account number;
   - currency;
   - balance.
4. A plain `<table>` (or `<ul>`) is completely fine. No CSS.

## Concepts practised

- reusing the service layer from a second presentation layer;
- mapping domain objects to a display DTO;
- `th:each` iteration;
- keeping the `Controller → Service → Repository` boundary clean.

## Done when

- the data comes through `AccountService`, not the repository directly;
- nothing about the accounts is hard-coded in the HTML.
