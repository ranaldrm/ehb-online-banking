# EHB Ticket TH-01 — Get Ready for Thymeleaf

## Objective

Make sure the project can serve server-rendered HTML pages with Thymeleaf, and
confirm the application still builds and all existing tests pass.

> **New to all of this?** Read the "Background for beginners" box below before
> you touch any code. The rest of this stage will make much more sense once you
> have the mental model.

---

## Background for beginners

### What is a server-rendered page?

Up to now, EHB has only spoken **JSON**. A tool like Postman sends an HTTP
request, and your `@RestController` sends back raw data:

```json
{ "accountNumber": "1111", "currency": "GBP", "balance": 500.00 }
```

That is perfect for machines, but a human in a web browser wants to see a
**web page** (HTML), not JSON.

A *server-rendered* page means: the Java server builds the finished HTML text
itself and sends that whole HTML document to the browser. The browser just
displays it. No JavaScript, no separate API call.

### What is Thymeleaf?

Thymeleaf is a **template engine**. A template is an HTML file with a few extra
special attributes (all starting with `th:`). When a request comes in, Spring
hands your data to Thymeleaf, Thymeleaf fills the placeholders in the template,
and the result is plain HTML.

Think of it as a mail-merge for HTML:

```text
template (HTML with gaps)  +  your Java data  =  finished HTML
```

### What is a Spring Boot "starter"?

A *starter* is a single Maven dependency that pulls in a whole bundle of
related libraries that are known to work together, already version-matched for
your Spring Boot version. For example:

- `spring-boot-starter-web` → everything needed to serve HTTP + build REST APIs.
- `spring-boot-starter-thymeleaf` → the Thymeleaf engine + the glue code that
  makes Spring MVC use it automatically.

You do not have to wire these together by hand. That wiring is what people mean
by **auto-configuration**: when Spring Boot sees the Thymeleaf starter on the
classpath at startup, it automatically creates and configures a Thymeleaf
"view resolver" bean for you.

## Step 1 — Inspect before you change anything

Open and read:

- `pom.xml` — look at the `<dependencies>` section;
- `src/main/java/com/ehb/banking/EhbBankingApplication.java` — the entry point;
- the `src/main/resources` folder — what is in there already?

## Step 2 — Check whether Thymeleaf is already present

> **Heads up:** in this project the Thymeleaf starter has *probably already been
> added*. Your first job is to look, not to blindly paste a dependency.

Search `pom.xml` for this:

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-thymeleaf</artifactId>
</dependency>
```

- **If it is already there:** you have nothing to add. Confirm that
  `spring-boot-starter-web` is *also* still there (it must stay — it is what
  serves HTTP and runs your REST controllers).
- **If it is missing:** add the dependency block shown above, in the same
  `<dependencies>` section as the other starters. Do not add a `<version>` —
  the Spring Boot dependency management picks the correct version for you.

## Step 3 — Do NOT touch the REST controllers

Leave every `@RestController` exactly as it is. Adding Thymeleaf does not change
them. REST and HTML pages happily live side by side.

## Step 4 — Verify

Rebuild and run the whole test suite:

```bash
mvn test
```

Then start the application:

```bash
mvn spring-boot:run
```

and confirm an existing REST endpoint still works, for example in a browser or
Postman:

```text
GET http://localhost:8080/api/status
```

You should still see:

```text
Hello, from Edinburgh Hanoverian Bank
```

Do **not** build any UI yet. This ticket is only about confirming the
foundation.

## Concepts practised

- Maven dependencies and Spring Boot starters;
- auto-configuration;
- the idea of a server-side template engine sitting next to an existing REST API.

## Questions you should be able to answer

1. What does the `spring-boot-starter-thymeleaf` dependency actually give you?
2. Why don't you have to write any code to create a Thymeleaf engine yourself?
3. Why do the `/api/...` REST endpoints keep working after Thymeleaf is added?

## Done when

- `pom.xml` contains both `spring-boot-starter-web` and
  `spring-boot-starter-thymeleaf`;
- `mvn test` is green;
- `GET /api/status` still returns its plain-text greeting.
