# EHB Ticket TH-02 — Render Your First Thymeleaf Page

## Objective

Create the simplest possible server-rendered EHB page: a bit of HTML with a
heading, served by a Spring MVC `@Controller`. No banking data yet.

---

## Background for beginners

### `@RestController` vs `@Controller`

You already know `@RestController`. When a method on a `@RestController` returns
a `String`, Spring sends that **string straight back to the client as the
response body**:

```java
@RestController
public class StatusController {
    @GetMapping("/api/status")
    public String getStatus() {
        return "Hello, from Edinburgh Hanoverian Bank"; // this exact text is the response
    }
}
```

A plain `@Controller` behaves differently. When one of its methods returns a
`String`, Spring treats that string as a **view name** — the name of a template
to render:

```java
@Controller
public class SomeController {
    @GetMapping("/hello")
    public String hello() {
        return "greeting"; // NOT the response text — it means "render greeting.html"
    }
}
```

Spring then looks for `src/main/resources/templates/greeting.html`, renders it
with Thymeleaf, and sends the resulting HTML to the browser.

So the single most important idea in this ticket is:

```text
@RestController + return "x"  →  the client receives the text "x"
@Controller     + return "x"  →  the client receives templates/x.html rendered as HTML
```

### Where templates live

```text
src/main/resources/templates/   ← Thymeleaf looks here by default
```

A returned view name of `"bankhome"` maps to
`src/main/resources/templates/bankhome.html`.

## Worked example (a *different* page, so you still write the EHB one yourself)

Here is a complete mini example for an imaginary `/hello` page. Study the shape,
then build the real EHB page in your own controller/template.

**Controller:**

```java
package com.example.demo;

import org.springframework.stereotype.Controller;
import org.springframework.web.bind.annotation.GetMapping;

@Controller
public class GreetingController {

    @GetMapping("/hello")
    public String hello() {
        return "greeting"; // -> templates/greeting.html
    }
}
```

**`src/main/resources/templates/greeting.html`:**

```html
<!DOCTYPE html>
<html xmlns:th="http://www.thymeleaf.org">
<head>
    <title>Greeting</title>
</head>
<body>
    <h1>Hello there</h1>
</body>
</html>
```

The `xmlns:th="http://www.thymeleaf.org"` namespace is what lets you use
`th:...` attributes later. Add it now even though this first page has none.

## Your task

1. There is already a `UIController` at
   `src/main/java/com/ehb/banking/controller/UIController.java`, annotated with
   `@Controller`, mapping `GET /` to the view name `bankhome`. Open it and read it.
2. There is already a template at `src/main/resources/templates/bankhome.html`.
   Open it. It currently has only a bare `<h1>` and no proper HTML structure.
3. Flesh the template out into a real HTML document with:
   - a `<!DOCTYPE html>`;
   - an `<html xmlns:th="http://www.thymeleaf.org">` root (you will need the
     `th` namespace in the next ticket);
   - a `<head>` with a `<title>`;
   - a `<body>` containing an `<h1>EHB Online Banking</h1>` heading.
4. No CSS. No JavaScript.

> **Likely bug to watch for.** Open the imports at the top of `UIController`.
> If you see a `Model` import, check *which* `Model` it is. The correct Spring
> type is `org.springframework.ui.Model`. An IDE auto-complete can easily import
> the wrong one (for example a logging library's `Model` class). You do not use
> `Model` in this ticket yet, but you will in TH-03 — if it is the wrong import,
> fix it to `org.springframework.ui.Model` (or just delete the unused import for
> now and re-add the correct one in TH-03).

## Verify

Start the app and visit:

```text
http://localhost:8080/
```

You should see your heading rendered as normal HTML. Right-click → "View page
source" in the browser: you should see ordinary `<html>...</html>` with no
`th:` attributes left in it (Thymeleaf strips those out when rendering).

Also confirm `GET /api/status` still returns its JSON/plain-text greeting — the
two worlds coexist.
